# ADR 0003: 見出し認識チャンク分割と pypdf の採用

## ステータス

Accepted

## コンテキスト

取り込み対象の Bedrock ユーザーガイドは 66MB・5,496 ページの PDF。
outline (ブックマーク) に 3〜4 階層・5,180 エントリの見出し構造がある。
固定長分割だと見出しをまたいで無関係な内容が混ざり、検索精度と出典精度が落ちる。

PDF ライブラリは PyMuPDF (AGPL-3.0) と pypdf (MIT) を比較した。
公開リポジトリで AGPL の伝播を避けたいため **pypdf** を採用する。outline からページ番号も取得できる。

## 決定

**セクション境界をまたがない 2 段階分割**とする。

1. outline から各ページの「最も深い見出し」を逆引きし (`parse.py: section_for_page`)、同一セクションのページをまとめる
2. セクション内は文字数ベースのスライディングウィンドウ (**1500 文字 / オーバーラップ 200 文字**)。
   分割点は段落 (`\n\n`) → 改行 → 半角スペースの優先順で探し、無ければ機械的に切る (`chunk.py: _window_split`)
3. 100 文字未満の極端に短いチャンクは、同一セクション内の直前チャンクに吸収する

目次セクション (`Table of Contents`) はページ番号の羅列で検索価値がないため、取り込み対象から除外する (`ingest.py`)。

## 影響

- 目次を除く 5,476 ページ → 約 6,483 チャンク、約 195 万入力トークン (Cohere Embed v4)
- `--dry-run` で投入前に規模を確認できる
- window / overlap を変えると全チャンクの `content_hash` が変わる (評価への影響は [ADR 0007](0007-eval-with-ragas-subset.md))
